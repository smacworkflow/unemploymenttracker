# Structural Unemployment Tracker

A self-updating dashboard that tracks the "hiring-freeze / no-backfill" structural-unemployment
signature in U.S. labor data (BLS Employment Situation + JOLTS, DOL jobless claims), sourced from FRED.

Every month a GitHub Action re-pulls the data, rebuilds the page, and redeploys to GitHub Pages —
no server, no API key, no manual step.

## How it works

- `dashboard_template.html` — the page (Chart.js, all logic) with a `__FRED_DATA__` placeholder.
- `build.py` — fetches ~14 FRED series (CSV download endpoint) and writes `_site/index.html`.
- `.github/workflows/deploy.yml` — runs `build.py` and deploys to Pages on a monthly cron,
  on every push to `main`, and via manual "Run workflow".

## One-time setup (~3 minutes)

1. **Create a new GitHub repo** (public is simplest for free Pages). Name it whatever you like,
   e.g. `unemployment-tracker`.

2. **Upload these files** to the repo root, keeping the folder structure:
   ```
   build.py
   dashboard_template.html
   .github/workflows/deploy.yml
   .gitignore
   README.md
   ```
   Easiest: on the repo page click **Add file → Upload files**, drag everything in, commit.
   (The `.github/workflows/` path must be preserved — if the web uploader flattens it, create the
   file via **Add file → Create new file** and type the path `.github/workflows/deploy.yml`.)

3. **Enable Pages via Actions:** repo **Settings → Pages → Build and deployment → Source = GitHub Actions**.

4. **Run it once:** go to the **Actions** tab → "Build & deploy unemployment tracker" → **Run workflow**.
   When it finishes (~1 min), your site is live at:
   `https://<your-username>.github.io/<repo-name>/`

That's it. From then on it refreshes itself on the 10th of each month.

## Changing the schedule

Edit the `cron` line in `.github/workflows/deploy.yml`. It's in UTC.
`"0 12 10 * *"` = 12:00 UTC on the 10th. (The BLS jobs report is the first Friday; JOLTS lags ~a month.
The 10th is a safe buffer so both are on FRED.)

## Custom domain (optional)

Settings → Pages → Custom domain. Add a `CNAME` DNS record at your registrar pointing to
`<your-username>.github.io`, enter the domain in that box, and check "Enforce HTTPS".

## Notes

- All data is public (FRED / BLS / DOL). Nothing sensitive is committed.
- `_site/` is generated by the build and git-ignored; you never edit it by hand.
- To change what's on the page, edit `dashboard_template.html` (keep the `__FRED_DATA__` placeholder).
- This is an analytical tool, not investment advice.
